# WideGold V1 代码结构与核心模块

本文按“从入口到核心”的顺序说明代码如何阅读和扩展。

## 1. 根目录

```text
apps/                 可运行应用入口
src/widegold/         核心 Python package
configs/              bootstrap 配置
migrations/           Alembic migration
scripts/              部署/测试/运维脚本
infra/                Docker/Nginx/PostgreSQL
fixtures/             契约与 Mock fixture
tests/                自动化测试
docs/                 项目文档
```

## 2. `apps/api/`：HTTP 边界

`apps/api/main.py` 创建 FastAPI 应用并挂载 Router。

主要 Router：

- `auth.py`：Session 登录/登出/当前用户；
- `dashboard.py`：最新 Published Snapshot；
- `assets.py`：资产当前值和历史；
- `events.py`：结构化事件与证据；
- `admin.py`：系统诊断、Run、Runtime Config、Factor Health、Audit；
- `research.py`：Research 流程；
- `scenarios.py`：Scenario；
- `ingest.py`：机器推送 Indicator。

API 层不直接做完整分析，而是通过 Command/Dispatcher 触发 Prefect。

## 3. `apps/web/`：前端

当前 V1 前端以 `main.tsx` 为单入口，主要负责：

- 读取 `/api/v1/dashboard/current`；
- 管理员登录；
- 触发 Preview；
- Run 状态与 SSE Trace；
- 资产历史 ECharts；
- Factor Health；
- Runtime Config / Audit / Diagnostics。

这是 V1 的轻量 UI，未来可再按 feature 拆分页面和组件，但不影响后端契约。

## 4. `src/widegold/data/`：事实获取

数据层职责是“拿到事实”，不做最终投资判断。

主要模块：

- `indicators.py`：Indicator 基础逻辑；
- `tool_factor_collector.py`：外部工具/因子采集组合；
- `providers/`：FRED、AKShare、NBS、External Bridge、Prepared/Mock Provider。

Provider 返回标准结构，并携带来源、时间、状态、warnings。

## 5. `src/widegold/external_bridge/`

这是一个单独的免费源适配层：

- `models.py`：HTTP Contract；
- `service.py`：capability 分发；
- `storage.py`：SQLite snapshot/cache；
- `adapters.py`：5 个免费 Adapter；
- `apps/external_bridge/main.py`：`/health /capabilities /fetch`。

当前 Bridge Build 标识：`2026.09.11-free-sources-v3.1`。

## 6. `src/widegold/engine/`：确定性核心

### `indicator_features.py`

把原始 Observation 变成滚动、变化、标准化等可供因子计算的特征。

### `factor_calculators.py`

将 33 个 Required Indicator 组合成 27 个逻辑因子的输入。资产级因子会生成多个 scope。

### `factor_resolution.py`

负责：

- 当前输入有效性；
- Last-Known-Good；
- stale/partial/unavailable；
- reliability/coverage；
- asset scoped 状态。

### `rules.py`

处理冲突规则、相关组封顶和风险标记。

### `scoring.py`

把 Factor State、Sensitivity、Reliability 等合成为方向分和 0~100 Asset Score。

### `confidence.py`

将 coverage/source quality/agreement/stability/context 等组合成 Confidence。

### `quality.py`

判断 Preview/Publish 是否允许。特别区分：

```text
总体 coverage
fresh coverage
LKG coverage
```

LKG 可以支持 Preview，但不能单独产生新的 Published Snapshot。

## 7. `src/widegold/llm/`

- `router.py`：从 Runtime Config 读取 alias 与 route；
- `service.py`：执行结构化模型调用与 fallback；
- `providers/http_compatible.py`：OpenAI-compatible HTTP 适配；
- `schemas/llm.py`：ModelExecution 等强类型契约。

业务代码使用 `qwen_fast / deepseek_* / gpt_expert` 等 alias，而不是硬编码具体模型。

## 8. `src/widegold/graphs/`

### Event Intelligence

`graphs/event_intelligence/` 将 NewsCluster 转成 StructuredEvent。单个 cluster 的 LLM 失败会返回结构化 warning，避免拖垮整个 Analysis。

### Explanation

Explanation 只解释已经得到的 Score/Factor，不重新创造最终数值判断。

### Factor Research

用于研究候选因子、规则和证据，生产修改仍需要人工审批。

### Scenario

情景分析写独立结果，不覆盖正式 Score。

## 9. `src/widegold/workflows/prefect/`

`analysis_flow.py` 是日常主流程。它把数据采集、新闻、事件、因子、评分等拆成 Prefect Task，并在最后调用 `run_analysis()` 完成统一持久化与状态流转。

其他 Flow：

- `research_flow.py`；
- `replay_flow.py`；
- `deployments.py`。

`prefect.yaml` 定义 deployment 与 18:10 收盘调度。

## 10. `src/widegold/services/`

Service 是“应用用例层”。典型模块：

- `analysis.py`：核心业务 Run；
- `dispatcher.py`：FastAPI → Prefect；
- `indicator_collection.py`：采集编排；
- `news_collection.py` / `news_clustering.py`；
- `factor_health.py`；
- `runtime_config_admin.py`；
- `replay.py` / `calibration.py`；
- `trace.py`：低频业务 Trace。

## 11. Repository 与 DB

`repositories/` 封装数据读写，避免业务代码到处直接 `session.execute()`。

`db/models.py` 定义 SQLAlchemy 模型，`migrations/` 是正式 Schema 演进来源。

生产启动时使用：

```text
postgres healthy
→ alembic upgrade head
→ seed reference/runtime config/admin
→ setup langgraph
→ start services
```

## 12. Config

`configs/` 中的 YAML 不是生产唯一真相，而是 canonical bootstrap baseline。

生产运行：

```text
reference.config_versions
        ↓
      ACTIVE
        ↓
 Runtime Config Loader
```

一次 Analysis 开始后冻结 VersionSnapshot，运行中途配置变化不会污染当前 Run。

## 13. 从一次按钮点击理解代码调用

```text
React Admin
  ↓ POST /api/v1/admin/analysis/run
FastAPI Router
  ↓
AnalysisCommand/Dispatcher
  ↓
Prefect Deployment
  ↓
analysis_pipeline
  ↓
IndicatorCollectionService / NewsCollectionService
  ↓
Event Graph
  ↓
Factor Calculator / Resolver
  ↓
Score / Confidence / Quality
  ↓
Repository persistence
  ↓
PREVIEW_READY
  ↓
管理员显式 Publish
```

阅读源码时建议从 `apps/api/routers/admin.py` → `services/dispatcher.py` → `workflows/prefect/analysis_flow.py` → `services/analysis.py` → `engine/` 这条线开始。
