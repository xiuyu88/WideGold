## 3. Indicator 与 Factor 分离

WideGold 不把某条原始指标直接当成最终 Factor。

```text
Indicator
   ↓
Feature / Normalization
   ↓
Factor
   ↓
Asset-Factor Sensitivity
   ↓
Asset Score
```

这样可以更换数据源而不改变经济语义，也能避免把一个指标的短期异常直接变成资产结论。

## 4. Point-in-Time

宏观/低频数据必须保存：

```text
observation_date
release_ts
ingest_ts
revision_vintage
definition_version
source_id
```

历史 Replay 查询必须满足：

```text
release_ts <= data_cutoff_ts
```

禁止用今天修订后的“最新值”替代历史当时市场可见值。

## 5. Factor State

统一范围：

```text
[-100, +100]
```

语义：正值代表“对该资产族环境更支持”，而不是原始指标上涨。

同时保留：

```text
level
trend
surprise
event
reliability
coverage
status
quality_flags
```

## 6. Missing / Stale

缺数据不是 0 分。

```text
UNAVAILABLE
→ 从有效分母剔除
→ coverage 下降
→ confidence 下降
```

旧值 fallback 必须：

```text
STALE / Last-Known-Good
```

不能伪装成最新数据。

## 7. 评分

核心思想：

```text
Factor State
× Asset Sensitivity
× Reliability
× Horizon Weight
× Regime Multiplier（V1预留）
```

合并为 Direction Score，再映射到 0~100：

```text
AssetScore = clip(50 + DirectionScore / 2, 0, 100)
```

用户标签：

```text
80~100  强势偏积极
65~79   偏积极
45~64   中性/观察
30~44   偏谨慎
0~29    强风险警示
```

## 8. Confidence

Score 与 Confidence 分离。V1 工程先验：

```text
Coverage          30%
Source Quality    25%
Agreement         20%
Stability         15%
Context Certainty 10%
```

这些参数是配置基线，不是已校准的统计真理。

## 9. Correlation / Conflict

同一经济机制不能重复满额计分。例如黄金的：Fed 鸽派、实际利率下降、美元走弱高度相关，需要通过 correlation group / group cap 防止重复放大。

冲突规则也会生成 Risk Flag，例如“流动性改善但增长/盈利未确认”。

## 10. Quality Gate

Quality Gate 至少区分：

```text
Preview 是否可生成
Publish 是否可生成
```

新数据不足时，可以生成 Preview；但 Last-Known-Good 不能把旧信息包装成今天的新正式结论。

## 11. 配置治理

生产 Weight、Factor、Rule、Prompt、Data Definition、Model Routing 均版本化。

Git YAML：

```text
bootstrap / canonical baseline
```

PostgreSQL `reference.config_versions`：

```text
production runtime source
```

生产变更必须经过状态流转和 Audit。

## 12. 研究先验声明

上传的因子准则和配置模板明确把敏感度与阈值定位为 engineering prior / research prior。真正用于投资研究之前，还需要：

- point-in-time walk-forward；
- 因子状态算法校准；
- 敏感度矩阵校准；
- Regime 条件化；
- Confidence calibration。
