# WideGold V1 测试与验收说明

## 1. 测试目标

WideGold 不只检查“页面能打开”，还要验证：

- Engine 结果可复现；
- Schema/Contract 不漂移；
- Point-in-Time 不穿越；
- External 失败可控降级；
- Quality Gate 能阻止错误发布；
- Runtime Config 可冻结/激活；
- Docker 冷启动和初始化可重复；
- 前端能构建；
- Secret 不进入代码包。

## 2. 测试分层

### Unit

测试 Factor State、规则、Score、Confidence、Quality Gate。

### Contract

测试 ProviderResult、External Contract、Machine Output、Schema。

### Integration

测试 Indicator → Factor → Score → Snapshot。

### Replay / Calibration

测试 point-in-time Replay、版本对比、T+1/T+5/T+20 后验评估。

## 3. 本地 Python 测试

安装：

```bash
python -m pip install -e ".[dev]"
```

运行：

```bash
pytest -q
python -m compileall apps src scripts tests
```

## 4. 前端测试

```bash
cd apps/web
npm install
npm run build
```

当前前端没有单独 Jest/Vitest 套件，生产构建是最基本的 TypeScript/Vite Gate。

## 5. Docker Compose 静态验证

```bash
docker compose config
```

这一步不需要启动全部业务流程，用于发现 YAML、变量和服务依赖错误。

## 6. External Bridge Smoke

```bash
python scripts/external_bridge_smoke.py
```

它不会调用 LLM。`require_data=False` 时，免费源受披露频率或 warm-up 影响可出现 WARN/WARM，但脚本结尾应：

```text
failures=0
```

7 天以上快照积累后，可以使用更严格的数据验收（如果当前脚本支持该参数）：

```bash
python scripts/external_bridge_smoke.py --require-data
```

## 7. Docker E2E

不触发新的真实分析：

```powershell
.\scripts\docker-e2e.ps1
```

检查：API、Readiness、Prefect、Admin、Runtime Config、Dashboard、Factor Health。

显式 Live Analysis：

```powershell
.\scripts\docker-e2e.ps1 -Analysis
```

后者可能调用付费 LLM，禁止在普通 CI 反复运行。

## 8. Release Gate

Windows：

```powershell
.\scripts\release-gate.ps1 -RequireDocker
```

Linux：

```bash
./scripts/release-gate.sh --require-docker
```

Gate 主要覆盖：pytest、compileall、runtime config、YAML、machine output、Alembic、secret scan、frontend build、docker compose config。

## 9. 一键无 Live Analysis 验收

Windows：

```powershell
.\scripts\quicktest.ps1
```

Linux：

```bash
./scripts/quicktest.sh
```

如果明确需要追加 Live Preview：

```powershell
.\scripts\quicktest.ps1 -LiveAnalysis
```

## 10. Publish 验收

Live Analysis 成功并不等于允许 Publish。至少检查：

```text
PREVIEW_READY
Quality Gate passed_for_publish = true
fresh coverage 达标
没有关键 PIT violation
没有关键 schema failure
```

如果 `passed_for_preview=true` 但 `passed_for_publish=false`，这代表系统保护正常，不能为了“验收全绿”绕过 Quality Gate。

## 11. 当前实机验证事实

项目曾在 Windows 10 + Docker Desktop 上完成：

- PostgreSQL / Redis / API / Web / Prefect / Nginx 的容器化运行；
- Admin 登录；
- Runtime Config；
- Dashboard / Factor Health；
- External Bridge V3.1：DR007、WGC、Eastmoney 源已实测；
- Prefect Flow/Task 实机执行；
- Preview 主评分链完成。

同时保留两个已知事实：

- Event Intelligence 的真实 LLM extraction 曾出现 fallback exhausted；
- 最新真实 Preview fresh coverage 未达到 Publish Floor，Quality Gate 正确拒绝新 Publish。

这两个状态应记录为已知限制，而不是改测试绕过。
