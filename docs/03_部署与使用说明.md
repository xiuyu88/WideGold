# WideGold V1 部署与使用说明

## 1. 推荐环境

### Windows

- Windows 10/11 64 位；
- Docker Desktop；
- PowerShell 5.1+ / PowerShell 7；
- Python 3.11；
- 可选 Conda 环境。

### Linux

- Docker Engine；
- Docker Compose v2；
- Python 3.11。

正式运行主要依赖 Docker，本机 Python 主要用于辅助测试和脚本。

## 2. 首次配置

Windows：

```powershell
cd D:\path\to\widegold-agent
.\scripts\init-final-env.ps1
```

Linux：

```bash
cp .env.final.example .env
```

至少修改：

```dotenv
POSTGRES_PASSWORD=强密码
WIDEGOLD_BOOTSTRAP_ADMIN_PASSWORD=至少8位密码
FRED_API_KEY=你的FREDKey
DEEPSEEK_API_KEY=你的模型Key
```

`WIDEGOLD_EXTERNAL_INDICATOR_API_KEY` 是 WideGold 与本地 External Bridge 的内部认证密钥，不是需要购买的 Vendor Token。Windows 初始化脚本会自动生成。

## 3. 最小启动

Windows：

```powershell
.\scripts\quickstart.ps1
```

Linux：

```bash
./scripts/quickstart.sh
```

等价核心命令：

```bash
docker compose up -d --build
```

Compose 会自动处理 migration、seed、LangGraph 初始化和 Prefect deployment。

## 4. 首次启动后的检查

```powershell
docker compose ps
```

关键服务应为：

```text
postgres          healthy
redis             healthy
external-bridge   healthy
prefect-server    healthy
prefect-worker    Up
api               healthy
web               healthy
nginx             Up
```

访问：

```text
WideGold  http://localhost:8080
Prefect   http://localhost:4200
Bridge    http://localhost:9100/health
```

## 5. Runtime Config 激活

全新数据库一般会从 Seed 得到可运行配置。如果是从旧数据库升级，运行：

```powershell
docker compose run --rm db-seed
.\scripts\activate-final-config.ps1
```

脚本当前目标包括：

```text
INDICATOR_REGISTRY 1.6.0
MODEL_ROUTING      1.1.0
NEWS_COLLECTION   1.2.0
```

如果登录失败，先确认 `.env` 的管理员密码和数据库中已创建的账号一致。Seed 对已有管理员默认不会无条件覆盖密码。

## 6. 日常使用

### 查看正式结果

打开 `http://localhost:8080`。Dashboard 永远读取最新 Published Snapshot。

### 管理员手动运行

管理员点击“更新并分析”后：

```text
FULL_REFRESH + PREVIEW_ONLY
```

完成后先看 Factor Health / Coverage / Risk，再决定是否 Publish。

### Prefect

`http://localhost:4200` 用于观察：

- Flow Run；
- Task Run；
- Duration；
- Retry；
- Deployment；
- Work Pool。

## 7. 数据模式

正式链：

```dotenv
WIDEGOLD_DATA_MODE=raw_indicators
```

Mock/开发：

```dotenv
WIDEGOLD_DATA_MODE=mock
```

关闭真实采集：

```dotenv
WIDEGOLD_DATA_MODE=disabled
```

## 8. LLM

默认通过 `configs/models.yaml` + DB Runtime Config 路由。常用环境变量：

```dotenv
QWEN_API_KEY=
QWEN_BASE_URL=
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
GPT_COMPAT_API_KEY=
GPT_COMPAT_BASE_URL=
GPT_COMPAT_MODEL=
WIDEGOLD_LLM_MAX_OUTPUT_TOKENS=1200
```

如果不需要 L3，可不配置 GPT compatible key。

普通 E2E 不需要主动触发新 Live Analysis。只有显式 `-Analysis` 才进行一次完整 Preview。

## 9. External Bridge

独立测试：

```powershell
python scripts/external_bridge_smoke.py
```

非严格模式允许免费源的 `WARN/WARM/UNAVAILABLE`，但不允许脚本级 FAIL。

盈利预测需要时间积累 Snapshot。不要为了清理容器执行 `docker compose down -v`，否则 `external_bridge_data` 会被删除，warm-up 重新开始。

## 11. 备份与恢复

Windows：

```powershell
.\scripts\backup.ps1
.\scripts\restore.ps1
```

Linux：

```bash
./scripts/backup.sh
./scripts/restore.sh
```

执行恢复前应仔细检查目标库和当前容器状态。

## 12. 安全停止

保留所有 Volume：

```powershell
docker compose down
```

再次启动：

```powershell
docker compose up -d
```

除非明确希望清空历史，不要执行：

```powershell
docker compose down -v
```

## 13. 常见问题

### API 容器 healthy，但 E2E 等待失败

GitHub 版 `docker-e2e.ps1` 已使用“环境变量 → Compose port → `.env` → 默认端口”的解析顺序。先看输出中的：

```text
API URL
Prefect URL
```

### Nginx 502

先确认 API healthy：

```powershell
docker compose ps
curl.exe -i http://localhost:8080/health
```

必要时：

```powershell
docker compose restart nginx
```

### External 免费源失败

系统会降级，不应改成语义错误的 proxy。优先查看：

```powershell
docker compose logs --tail=300 external-bridge
```
